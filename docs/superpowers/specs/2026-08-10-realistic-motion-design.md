# AI 口播视频自然动作增强设计

## 目标

在现有 GPT-SoVITS、MuseTalk 1.5、FunASR 和 FFmpeg 本地流水线上增加自然动作阶段，使单张人物照片生成的视频除准确口型外，还包含克制的眨眼、眼神、眉毛、嘴角和头部微动作，同时保持人物身份、原始背景和 1920x1080 横屏构图稳定。

本方案必须在 Windows、RTX 4060 Laptop 8 GB 显存环境运行，不依赖收费云端接口。原有“仅口型”模式继续可用，作为快速模式和故障降级路径。

## 方案选择

采用 LivePortrait 生成自然动作底片，再由 MuseTalk 1.5 根据 GPT-SoVITS 音频精修口型：

1. GPT-SoVITS 生成克隆语音并释放显存。
2. LivePortrait 使用人物原图和预制动作模板生成自然动作底片并释放显存。
3. MuseTalk 1.5 使用自然动作底片和语音生成最终口型。
4. FunASR 生成时间轴，FFmpeg 完成字幕、色彩元数据和最终编码。

不采用 Ditto 作为主路径，因为其官方验证环境偏向 Linux、A100 和 TensorRT，当前 Windows 8 GB 设备上的部署与显存风险更高。也不只做后期缩放或随机眨眼，因为这类二维效果无法产生可靠的眼神、眉毛和头部姿态变化。

## 流水线

增强模式的阶段顺序为：

```text
setup -> voice -> motion -> lipsync -> subtitle -> render -> export
```

快速模式保持：

```text
setup -> voice -> lipsync -> subtitle -> render -> export
```

`motion` 阶段输出 `motion.mp4`。增强模式下，MuseTalk 的输入从 `avatar/avatar.jpg` 改为 `motion.mp4`；快速模式仍直接使用原图。最终 `talking.mp4`、`packaged.mp4` 和 `final.mp4` 的文件契约保持不变。

## 组件边界

### 自然动作适配器

新增独立 motion provider，负责：

- 校验 LivePortrait 运行目录、Python 3.10 环境、模型权重和动作模板。
- 创建本次任务的绝对路径配置和输出目录。
- 调用 LivePortrait 官方推理入口生成 25 fps 动作底片。
- 捕获标准输出、错误输出、超时和 CUDA 显存不足信息。
- 校验结果包含有效视频流、尺寸为偶数、帧率接近 25 fps，且时长覆盖音频。
- 将底片裁切或循环到音频时长，循环连接处使用短交叉过渡，避免突然跳帧。

motion provider 不负责语音、口型、字幕和最终编码，使 LivePortrait 的内部版本可以在不改变流水线调用方的情况下替换。

### LivePortrait 隔离环境

LivePortrait 使用独立 Python 3.10 虚拟环境和独立模型目录，不能修改当前项目主环境中的 PyTorch、MuseTalk 或 GPT-SoVITS 依赖。安装脚本负责创建环境、拉取固定版本源码、下载模型并执行一次最小预检。

主进程通过子进程调用该环境。推理结束后子进程退出，确保 CUDA 上下文和显存被操作系统回收，再启动 MuseTalk。

### 动作模板

第一版提供一个 `steady` 模板，定位为稳重讲解：

- 首帧正脸、闭嘴或自然微张。
- 头部偏航和俯仰动作幅度小，目标不超过约 3 度。
- 包含自然眨眼、轻微眉毛和眼神变化。
- 肩部运动尽量小，避免全景照片中身体和背景变形。
- 模板时长 8 至 12 秒，可循环用于更长口播。

模板以 LivePortrait motion template 格式缓存。驱动视频仅用于离线生成模板，不参与每次口播推理。第一版仅实现 `steady`，不提前增加多风格选择。

### MuseTalk 接入

现有 MuseTalk provider 扩展为同时接受图片和视频输入。视频输入必须在推理前校验：

- 包含可解码的视频流。
- 帧率统一为 25 fps。
- 宽高为偶数。
- 时长不少于目标音频时长，允许最多 0.1 秒编码误差。

继续使用 MuseTalk 1.5、FP16、batch size 1。MuseTalk 仍是唯一的音频口型生成器，LivePortrait 不根据语音塑造嘴型，避免两个模型同时控制嘴部导致抖动。

### 时序与画面处理

LivePortrait 使用原图回贴或 stitching 能力，尽量只改变人物面部和头部，不重新生成背景。MuseTalk 后继续使用自身的人脸融合流程。最终 FFmpeg 阶段只做确定性的尺寸、帧率、字幕和编码处理，不添加随机镜头晃动。

第一版不默认启用 GFPGAN 或其他强人脸修复。此类模型可能改变五官和肤质，后续只作为可选的低强度 A/B 功能评估。

## 配置与界面

新增配置项：

```yaml
motion:
  enabled: true
  provider: liveportrait
  style: steady
  intensity: 0.35
  fps: 25
  timeout_seconds: 1800
```

命令行新增：

- `--motion-mode natural|off`，默认 `natural`。
- `--motion-style steady`，第一版只有该合法值。
- `--motion-intensity 0.0..1.0`，默认 `0.35`。

网页增加“自然动作”开关和动作强度控件。开关关闭时显示并执行现有快速模式。任务元数据记录实际模式、模板、强度和各阶段产物。

## 断点续跑

`motion.mp4` 纳入现有产物校验和 `--resume` 机制。动作模式、模板、强度、源图片摘要或目标音频时长发生变化时，旧动作底片不能复用；配置未变化且产物有效时可以跳过 motion 阶段。

从增强模式切换到快速模式时，不删除已有 `motion.mp4`，但 MuseTalk 必须明确使用原图。任何阶段失败都保留此前有效产物和日志。

## 错误处理与降级

- LivePortrait 未安装或权重不完整：环境预检失败并给出安装命令和缺失路径。
- CUDA 显存不足：记录错误，清理子进程；网页允许用户关闭自然动作后重试，不静默改变任务模式。
- 人脸检测失败：指出源图片或动作模板问题，不进入 MuseTalk。
- 动作底片损坏或时长不足：motion 阶段失败，不把半成品标记为完成。
- LivePortrait 超时：终止子进程，保留日志和任务配置。
- MuseTalk 处理动态底片失败：保留 `motion.mp4`，支持只重跑 lipsync 之后的阶段。

## 测试策略

### 单元测试

- LivePortrait 所需文件和独立解释器检查。
- motion 子进程命令、路径和参数生成。
- 图片、动作模板、动作强度和音频时长组成的缓存键。
- 动作底片帧率、时长、视频流和偶数尺寸校验。
- Pipeline 在 `natural` 与 `off` 模式下的阶段选择。
- `--resume` 对 motion 产物的跳过与失效判断。
- MuseTalk 对图片和视频两种输入的命令生成。
- Web 请求参数校验和元数据展示。

### 集成测试

- 使用短音频运行 LivePortrait，确认获得非静态的 25 fps 动作底片。
- 将动作底片送入 MuseTalk，确认输出同时含视频流和音频流。
- 在模拟 motion 失败时验证快速模式仍能单独运行。
- 验证每个 GPU 阶段使用独立进程，并在下一阶段前退出。

### 端到端验收

使用当前人物图片、参考声音和约 30 秒中文文案生成增强版与快速版两条视频。增强版必须满足：

- 输出为 1920x1080、25 fps、H.264/AAC、yuv420p 和 BT.709。
- 视频与音频时长误差不超过 0.1 秒。
- 30 秒任务不发生 CUDA OOM，峰值显存目标低于 7.5 GB。
- 存在可见但克制的眨眼、眼神和头部微动作。
- 嘴部与中文语音同步，不出现持续嘴周闪烁或明显融合边界。
- 人物身份、发型、球衣标志、手部和背景无明显漂移或变形。
- 动作模板循环点无明显姿态跳变。

最终保留增强版、快速版、各阶段日志和媒体探测结果，供人工并排验收。

## 实施范围

本轮实现一个 `steady` 动作模板、自然动作开关、LivePortrait 安装/预检、motion provider、流水线接入、网页参数、测试和一条真实验收样片。

本轮不实现全身或手势生成、自动根据文案选择多种动作模板、模型训练、云端 API、强人脸修复和 UI 视觉重做。这些能力只有在第一版身份稳定性和显存表现通过验收后再评估。
