# 本地 AI 口播视频修复设计

## 目标

完善 `D:\workspaces\ai-talking-video`，使其在当前 Windows 电脑上通过现有网页或命令行稳定生成本地 AI 口播视频。最终视频使用指定人物图片与背景、指定参考声音、中文口型同步和烧录字幕，不依赖云端生成接口。

## 已确认环境

- 操作系统：Windows。
- GPU：NVIDIA GeForce RTX 4060 Laptop GPU，8 GB 显存。
- Python：3.12.10。
- PyTorch：2.5.1+cu124，CUDA 可用。
- FFmpeg：8.1.2。
- 输出形态：横屏完整画面。

## 技术方案

采用以下本地流水线：

1. GPT-SoVITS 生成克隆语音。
2. 释放 GPT-SoVITS 占用的 GPU 显存。
3. MuseTalk 1.5 以 FP16 模式驱动人物图片的口型。
4. FunASR 从生成语音获取字幕时间戳。
5. FFmpeg 烧录字幕并统一编码最终视频。

不使用 LatentSync 1.6、Hallo、EchoMimic 等更高显存方案。LatentSync 1.5 虽可在 8 GB 显存运行，但更适合已有视频，当前静态全景图片场景优先使用 MuseTalk 1.5。

## 组件设计

### 素材准备

新增可重复执行的素材准备逻辑：复制人物图片到标准位置；将参考录音裁剪、转码为 GPT-SoVITS 可用的 WAV；保存参考文本。已存在且校验通过的标准素材不重复处理。

### 环境预检

预检不仅检查 Python 包是否可导入，还必须验证：

- GPT-SoVITS 配置引用的每个模型文件真实存在。
- CN-HuBERT 使用包含 `pytorch_model.bin` 的 Hugging Face 格式目录。
- MuseTalk 1.5 的 UNet、VAE、Whisper、DWPose 和面部分割权重完整存在，且没有 `.incomplete` 文件。
- 人物图片可由 OpenCV 解码且包含可检测人脸。
- 参考音频可由 FFmpeg 解码，时长处于有效范围。
- FFmpeg、ffprobe、CUDA 和可用显存满足运行要求。

预检失败时返回缺失文件的准确路径及修复建议，不进入长时间模型推理。

### 语音生成

语音适配器使用绝对模型路径，不能依赖进程当前工作目录。GPT-SoVITS 配置显式指定 v3 权重、BERT、CN-HuBERT 和参考音频。提示文本来自声音配置，不能用待生成文案冒充参考录音文本。

生成成功必须满足：输出 WAV 存在、可解码、包含非静音音频且时长大于零。完成后卸载模型并调用 CUDA 缓存清理，再进入口型阶段。

### 口型同步

口型适配器使用 MuseTalk 1.5 官方 CLI 契约。每次任务在输出目录下生成独立临时 YAML，其中包含人物图片绝对路径、语音绝对路径和结果名称。子进程工作目录固定为 MuseTalk 根目录，并传入：

- `--version v15`
- `--use_float16`
- 正确的 `--unet_model_path`
- 正确的 `--unet_config`
- 独立的 `--result_dir`

MuseTalk 使用 25 fps，与官方训练设置一致。成功判定包括子进程退出码为零、结果视频存在、包含视频流与音频流且时长合理。临时帧在成功后清理；失败时保留日志和配置以便诊断。

### 字幕生成

FunASR 使用生成后的语音创建分段时间戳。字幕结果为空、结束时间早于开始时间或超出音频时长时，阶段失败并给出明确原因。

最终字幕使用 ASS 或兼容的 FFmpeg 字幕滤镜烧录。样式为白色正文、黑色描边，位于画面下方安全区，不遮挡人物嘴部和球衣主要标志。

### 最终合成

最终合成统一使用 FFmpeg，不再依赖当前有嵌套片段错误的 MoviePy 路径。输出规格为：

- 分辨率：1920×1080。
- 帧率：25 fps。
- 视频编码：H.264 (`libx264`)。
- 音频编码：AAC。
- 像素格式：`yuv420p`。
- 画面：完整保留原图构图与背景。
- 文件名：`final.mp4`。

### 流水线与网页

保留现有 `setup -> voice -> lipsync -> subtitle -> render -> export` 阶段结构，但每个阶段必须只在产物校验成功后写入 `done`。元数据记录开始时间、结束时间、错误摘要、日志路径和产物信息。

网页继续显示各阶段的实时状态和日志。`--resume` 仅跳过通过产物校验的阶段；损坏或空文件必须重新生成。下载与文件接口必须限制在项目输出目录内，避免路径穿越。

## 错误处理

- 缺失模型：启动前失败，列出缺失权重。
- CUDA 显存不足：记录显存信息，清理模型后允许从当前阶段重试。
- MuseTalk 子进程失败：保存完整标准输出、错误输出和临时 YAML。
- FFmpeg 失败：保存完整命令和错误输出，不把部分文件标记为成功。
- 网页后台任务失败：状态设置为 `failed`，并向前端返回可读错误。
- 任一阶段失败：保留此前有效产物，支持断点续跑。

## 测试策略

### 单元测试

- 绝对模型路径与 GPT-SoVITS 配置生成。
- 参考声音查找和参考文本读取。
- MuseTalk 临时 YAML 及 CLI 参数生成。
- 输出文件校验和断点续跑判定。
- 字幕时间合法性与 ASS/SRT 生成。
- FFmpeg 最终编码命令。
- Web 文件接口的路径限制。

### 分阶段真实测试

- GPT-SoVITS 使用指定参考声音生成 5 至 10 秒语音。
- MuseTalk 1.5 使用指定 JPG 和测试语音生成口型视频。
- FunASR 对测试语音生成非空字幕。
- FFmpeg 输出可播放的 1920×1080 视频。

### 端到端验收

从网页输入一段 5 至 10 秒中文文案，最终生成 `final.mp4`。使用 ffprobe 验证：

- 分辨率为 1920×1080。
- 帧率为 25 fps。
- 同时包含 H.264 视频流和 AAC 音频流。
- 时长与生成语音一致，误差不超过 0.5 秒。
- 字幕非空并位于安全区。
- 人物、背景和原图构图完整保留。
- 嘴部区域随中文语音变化，视频帧不是静态复制。
